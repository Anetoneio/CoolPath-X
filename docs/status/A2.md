## Investigation Findings

### Problem 1: Multi-Crew Site Scheduling
- **Root Cause**: `scheduler.py` previously maintained a single `crew_cursor` time regardless of the `crews` parameter passed in the request. S01 (180 min work + 20 min rest = 200 min) advanced the single cursor from 07:00 to 10:20; S02 (120 min work + 15 min rest = 135 min) was dropped because `10:20 + 135 min = 12:35 > 12:00`.
- **Fix**: Replaced single cursor with a list of crew cursors (`[shift_start_min] * num_crews`). Each site in priority order is assigned to the earliest-available crew capable of completing the work and mandatory rest breaks before `shift_end_min`.
- **Contract Omission Rule**: `contracts/api.md` defines only `{"assignments": [...]}` with no schema field for omitted or unscheduled sites. Therefore, sites that cannot fit on any crew before shift end are omitted from `assignments`. With 2 crews and sites S01 + S02, both are scheduled.

### Problem 2: Heat Grid Coverage, Nearest-Cell Fallback & Site Exposure
- **Heat Grid Extent**:
  - Longitude: `[72.5400, 72.6200]`
  - Latitude: `[22.9850, 23.0620]`
- **Nearest-Cell Fallback Logic**:
  - Sites outside every heat-grid cell use the nearest cell if its edge is within `NEAREST_CELL_MAX_KM` (1.0 km).
  - The reason text flags the nearest-cell estimate, specifying the cell ID and distance in metres.
  - Per-site confidence in `scheduler.py` applies a penalty (`NEAREST_CELL_CONFIDENCE_PENALTY = 0.15`), giving 0.60 instead of 0.75.
  - Sites beyond 1.0 km retain the neutral `MID_RANGE_EXPOSURE = 50` fallback.
- **8-Site Table (Real Output with Nearest-Cell Fallback)**:

  | site | cell_for_point | nearest cell | distance m | exposure_score | Notes |
  |---|---|---|---|---|---|
  | S01 | None | C05 | 256.0 | 66 | Uses C05 (256m away, nearest-cell estimate) |
  | S02 | C09 | C09 | 0.0 | 56 | Inside cell C09 |
  | S03 | None | C05 | 20.5 | 56 | Uses C05 (20.5m away, nearest-cell estimate) |
  | S04 | None | C20 | 133.2 | 85 | Uses C20 (133.2m away, nearest-cell estimate) |
  | S05 | C01 | C01 | 0.0 | 84 | Inside cell C01 |
  | S06 | C05 | C05 | 0.0 | 61 | Inside cell C05 |
  | S07 | None | C18 | 2957.6 | 50 | Exceeds 1.0 km; mid-range fallback |
  | S08 | None | C18 | 1751.5 | 50 | Exceeds 1.0 km; mid-range fallback |

- **Code Verification**: The ray-casting implementation in `scoring.py` and coordinate passing order (`x=lon, y=lat`) are mathematically verified correct against an independent bounding box check. Mock data leaves S07 and S08 > 1 km outside; full municipal coverage requires A1 processed data.
- **Exposure Dependence on Shift Time**:
  - In `scoring.py`, temperature adjustment applies as `round(2.0 * max(0.0, forecast_temp - 25.0))`.
  - In Ahmedabad in November, cached forecast temperatures for 06:00 and 07:00 are ~18.7°C and ~18.5°C (both below 25°C baseline), producing 0 adjustment points.
  - For sites beyond 1.0 km (S07, S08), the score immediately falls back to `MID_RANGE_EXPOSURE = 50`. Shifting start times between 06:00 and 07:00 on out-of-grid sites yields 50 in both options.
