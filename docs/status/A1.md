## Blockers and Observations
- **Overpass Public Mirror Availability:**
  - `https://overpass-api.de/api/interpreter` experienced WinError 10060 connection timeouts from this environment.
  - `https://overpass.kumi.systems/api/interpreter` experienced read timeouts (>45-60s).
  - `https://overpass.osm.ch/api/interpreter` is Switzerland-only and returned 0 elements for India.
  - `https://overpass.openstreetmap.fr/api/interpreter` returned 403 Forbidden when default `OSMnx` or `Mozilla` user-agent / referer was used; resolved by setting custom `CoolPath/1.0` User-Agent and clearing `http_referer`. Successfully served all facilities and road network queries.
- **Drinking Water Sparsity in OSM:** Only about 2 mapped drinking-water points exist in OSM for this AOI (1 drinking water point, 1 water tap across 97 total facilities). Per strict project rules, no synthetic points were invented.
- **Shade Representation as Park Centroids:** "Shade" points in this dataset are predominantly park centroids (one single coordinate per park polygon). Consequently, mapped shade coverage appears denser than actual continuous shaded pedestrian walkway space; downstream routing and map display should not treat a park centroid as a precise, localized shaded shelter spot.

2. **Confidence scoring:**
   - Real Landsat data: `data_age` can be computed as days elapsed since `2026-05-15`, and `cloud` reflects `cloud_pct` (0%). If proxy mode is selected, `source` is `"proxy"` and confidence score reflects proxy discount.
   - All 97 facility features have `verified: false` (`source: "OpenStreetMap"`).

3. **Known limitations:**
   - Single-date satellite observation (15 May 2026); captures surface skin temperature, not near-surface ambient air temperature.
   - Only about 2 mapped drinking-water points exist in OSM for this AOI (97 facilities total: 2 water, 95 shade).
   - Parks are represented by single centroid points rather than area polygons; do not assume complete shade coverage across the entire park area.
   - None of the facilities have been field-verified.

4. **How to regenerate:**
   Run from the `CoolPath-X\` directory in PowerShell:
   ```powershell
   python data\scripts\build_heat_grid.py --mode landsat   # or --mode proxy
   python data\scripts\build_facilities.py
   python data\scripts\build_roads.py
   python data\scripts\validate_processed.py
   ```
   *Note*: `build_heat_grid.py --mode landsat`, `build_facilities.py`, and `build_roads.py` require internet access and may occasionally require a retry if public endpoints are under load.

5. **Upgrade path:**
   - If ground-truth municipal water taps are surveyed, placing a CSV at `data/manual/water_points.csv` (`name,lat,lon,checked`) will be automatically ingested by `build_facilities.py`.
   - Local raw GeoTIFFs can also be placed in `data/raw/landsat/` for offline processing.
